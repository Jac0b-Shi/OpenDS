# 协议要点

本文记录 OpenDS 实现所依赖的 USB/HID/音频协议要素，均可在 USB-IF 公开规范与设备实测中复核。

---

## 1. 设备身份

| 项 | USB 有线 | 蓝牙 |
| --- | --- | --- |
| VID / PID | `054C` / `0CE6` | 同 |
| 产品字符串 | `DualSense Wireless Controller` | 同 |
| 设备路径 | `USB\VID_054C&PID_0CE6` | `BTHENUM\...` |
| 接口组成 | 复合设备，MI_00 ~ MI_03 | Bluetooth Classic HID |

接口划分：

| 接口 | 类别 | 用途 |
| --- | --- | --- |
| MI_00 | UAC1 音频控制 | 音频功能单元、音量 |
| MI_01 / MI_02 | UAC1 音频流 | 扬声器（4ch OUT）、麦克风（2ch IN） |
| MI_03 | HID | 输入报告、输出报告 |

## 2. HID 报告

### 2.1 报告长度

| 模式 | 输入 | 输出 | Feature |
| --- | --- | --- | --- |
| USB | 64 | 48 | 64 |
| 蓝牙完整输入 / 普通输出 | 78 | 78（`0x31`） | 按报告 ID 而异 |

547 字节是 Windows HID 描述符声明的最大缓冲区长度，不能当作每个实际报告的长度。组合音频输出 `0x36` 为 398 字节。

### 2.2 输入报告（USB，报告 ID `0x01`）

64 字节。关键字段：

| 偏移 | 内容 |
| --- | --- |
| 0 | 报告 ID `0x01` |
| 1-4 | LX / LY / RX / RY |
| 5-6 | 扳机 L2 / R2 |
| 7 | 序号 |
| 8-10 | 方向键、面键、肩键与系统键 |
| 16-21 | 陀螺仪 XYZ（int16 LE） |
| 22-27 | 加速度计 XYZ（int16 LE） |
| 28-31 | IMU 时间戳 |
| 33-40 | 触摸点 1/2（各 4 字节） |
| 49-52 | 设备时间戳 |
| 53 | 电量与充电状态 |
| 54 | 连接状态 |

### 2.3 输出报告（USB，报告 ID `0x02`）

48 字节。首字节为报告 ID，以下偏移相对于随后的 47 字节载荷：

| 偏移 | 字段 | 说明 |
| --- | --- | --- |
| 0 | 有效标志 1 | 传统震动选择、触觉选择、右/左扳机、耳机/扬声器/麦克风音量、音频控制 |
| 1 | 有效标志 2 | 静音灯、音频静音、灯条颜色、灯光重置、玩家灯等 |
| 2-3 | 右/左马达 | 传统振动强度 |
| 4 | 耳机音量 | 0-255 |
| 5 | 扬声器音量 | 0-255 |
| 7 | 音频控制 | bit4-5 输出路由：`0x00` 耳机、`0x20` 双路、`0x30` 扬声器 |
| 10-20 / 21-31 | 右 / 左扳机 | 每侧 1 字节模式 + 10 字节参数 |
| 32-35 | 主机时间戳 | uint32 LE |
| 38 | 有效标志 3 | 亮度、渐变、改进震动选择 |
| 42 | 亮度 | 0 高 / 1 中 / 2 低 |
| 43 | 玩家灯 | 5 位掩码 |
| 44-46 | 灯条 R / G / B | 0-255 |

**注意**：`0x30` 路由只把**右声道**送往内置单声道扬声器。

### 2.4 蓝牙输出报告（报告 ID `0x31`）

78 字节，头部为 `0x31`、`seq << 4`、`0x10`，47 字节状态载荷从偏移 3 开始；偏移 74-77 为 CRC32。

### 2.5 CRC32

蓝牙报告末尾 4 字节为 CRC32；计算时包含 HIDP 类型前缀和报告 ID，排除末尾 CRC 字段。

| 参数 | 值 |
| --- | --- |
| 多项式 | `0xEDB88320`（标准反射 CRC-32） |
| 初始值 | `0xFFFFFFFF`；先纳入 HIDP 前缀：输入 `0xA1`、输出 `0xA2`、Feature `0xA3` |
| 输出 | 取反后小端写入 |

## 3. 音频通路

### 3.1 声道布局

UAC1 扬声器接口为 **4 声道 S16LE @48kHz** 等时 OUT：

| 声道 | 内容 |
| --- | --- |
| 0 / 1 | 前置左 / 右（扬声器音频） |
| 2 / 3 | 后音圈对（触觉 PCM） |

**触觉走 ch2/ch3**，与前置音频独立。部分游戏只写触觉通道，前置通道保持静音。

### 3.2 数据节奏

| 项 | 值 |
| --- | --- |
| 采样率 | 48000 Hz |
| 每 10ms 数据量 | 480 帧 × 4ch × 2B = **3840 字节** |
| 已观察到的主机批次 | 单次等时 OUT 提交 3840 字节；并非固定协议限制 |

### 3.3 蓝牙音频报告

回传到手柄时需要 Opus 编码：

| 报告 | ID | 长度 | 载荷 |
| --- | --- | --- | --- |
| 纯触觉 | `0x32` | 142 | 64B s8 立体声 |
| 纯音频 | `0x35` | 334 | 200B Opus |
| **组合** | `0x36` | 398 | 状态 47B + 触觉 64B + Opus 200B |

**必须使用 `0x36` 组合报告**。触觉与音频分两条报告发送会让序列号与间隔计数器每 tick 前进两次，导致音频流损坏。

`0x36` 布局：

```
[0]       0x36
[1]       seq << 4
[2..11]   0x91 0x07 0xFE 0x40×5 counter     会话块
[11..13]  0x90 0x3F                          状态块头
[13..60]  47 字节输出状态
[60..76]  零填充
[76..78]  0x92 0x40                          触觉块头
[78..142] 64 字节触觉 PCM
[142]     0x93 / 0x96                        扬声器 / 耳机路由
[143]     200
[144..344] 200 字节 Opus
[344..394] 零填充
[394..398] CRC32（HIDP 输出前缀 0xA2，再覆盖 [0..394)）
```

### 3.4 Opus 编码参数

| 参数 | 值 |
| --- | --- |
| 采样率 / 声道 | 48000 / 2 |
| 应用 | `OPUS_APPLICATION_AUDIO` |
| 帧长 | 10ms（480 samples） |
| 码率 | 160 kbps CBR |
| 复杂度 | 0 |

### 3.5 流初始化

打开蓝牙音频通道需要两步：

1. 发送 `0x32` init-prime（142 字节，含 47 字节输出状态）
2. 发送 **8 帧编码后的静音**（每 10.67ms 一帧）

缺少预滚时手柄会丢弃后续音频帧。

## 4. Feature 报告

| ID | 内容 | OpenDS 预载长度（含报告 ID） |
| --- | --- | --- |
| `0x05` | 校准数据（陀螺仪/加速度计零点与量程） | 41 |
| `0x09` | 配对信息（MAC、设备标识） | 20 |
| `0x20` | 固件版本与构建时间 | 64 |

OpenDS 验证蓝牙 Feature 末尾 4 字节的 `0xA3` CRC 后，将这 4 字节清零，保留固定长度，以匹配本机真实 USB 报告。普通 DualSense 使用 289 字节 HID 描述符；F6-F9 属于 DS5Dongle 适配器的扩展配置报告，未纳入真机配置。Edge 保留独立配置，仍需真机验收。
