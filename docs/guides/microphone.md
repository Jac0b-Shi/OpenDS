# 麦克风

麦克风是实验功能，默认关闭。开启后手柄的麦克风音频会转发到虚拟 USB 麦克风接口。

## 开启

在「连接与反馈」里打开麦克风转发。

麦克风的采集状态可能持续到蓝牙连接结束。关闭设置后要完全停止物理采集，需要停止桥接并重新连接手柄。

## 增益

0–50 dB 可调，默认 0 dB。

增益带峰值限幅：超过满量程的样本会被压住，不会削波成方波。监视页面的图例会显示当前增益和限幅状态。

## 缓冲

`microphone_buffer_ms`，范围 16–512 毫秒，默认 128。

蓝牙音频包的到达节奏不均匀，这个缓冲把突发到达的包平滑成 USB 的固定帧节拍。

**代价是延迟**：缓冲里存多长的音频，声音就晚多久送出。这个延迟是单向叠加的，语音聊天时对方听到你的声音会晚同样时长。

| 缓冲 | 额外延迟 | 适用场景 |
| --- | --- | --- |
| 32 毫秒 | 很短 | 环境干净、追求跟手 |
| 64 毫秒 | 约 0.06 秒 | 语音聊天，延迟优先 |
| 128 毫秒（默认） | 约 0.13 秒 | 通用 |
| 256 毫秒 | 约 0.26 秒 | 无线干扰大、频繁欠载 |
| 512 毫秒 | 约 0.5 秒 | 只在欠载无法消除时使用 |

超过 256 毫秒后，语音通话里对方能明显感觉到你回应变慢；512 毫秒已经接近对话节奏的上限。欠载消失后应该把缓冲调回来。

## 测试窗口

「连接与反馈」→「麦克风测试…」。

| 按钮 | 作用 |
| --- | --- |
| 录音 5 秒 | 采集 5 秒蓝牙端音频 |
| 回听 USB 端 | 播放虚拟 USB 麦克风接口实际收到的内容 |
| 回听蓝牙端 | 播放手柄原始解码结果 |
| 清除录音 | 丢弃本次录音 |

回听使用系统默认播放设备。关闭窗口会清除录音。

两个回听按钮的差异就是问题所在：

- **两端都正常**：链路完好
- **蓝牙端正常、USB 端异常**：问题在转发或缓冲
- **两端都异常**：问题在解码或手柄侧

底部显示蓝牙 Opus 包数、解码样本数、USB 接收帧数、USB 欠载次数、丢弃毫秒数和当前缓冲。

## 诊断

| 现象 | 含义 | 处理 |
| --- | --- | --- |
| USB 欠载次数持续增长 | 缓冲不够，供给跟不上 | 调大 `microphone_buffer_ms` |
| 解码失败增长 | Opus 包本身损坏 | 重新连接手柄；持续出现则记录蓝牙环境 |
| 丢弃毫秒数增长 | 队列溢出 | 同上，加大缓冲 |

监视页面（概览 → 实时监视）的麦克风轨道可以同时看到源信号和转发信号的波形，用来判断问题出在解码前还是转发后。
